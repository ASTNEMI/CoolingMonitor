# 尼伸 CX2 Pro 遥测协议

## 发现与初始化

`BleHelper.startScan` 按设备类型选择确切广播名。水冷分支使用 `NiShen-CX2-pro`，随后经 `ScanFilter.Builder.setDeviceName` 进行低功耗蓝牙扫描。其他分支包括液冷 `NiShen`、风冷 `NiShen_FL` 和显示屏型号 `NinShen_BH3pro`，这些型号的兼容性未纳入交付验证。

连接路径为 `connectGatt(false)` → 请求高连接优先级 → 请求 MTU 512 → 发现服务 → 订阅 FF22 的 CCCD → 首页发送查询。CCCD 写入成功通过回调确认。官方代码在目标路径没有主动调用系统配对或发送账户认证、密钥、初始化配置指令。特定固件是否要求系统配对仍待实机确认。

| UUID | 官方调用 |
|---|---|
| `0000ff20-0000-1000-8000-00805f9b34fb` | 服务发现后查找 |
| `0000ff21-0000-1000-8000-00805f9b34fb` | 特征写入，接收查询 |
| `0000ff22-0000-1000-8000-00805f9b34fb` | Notify 特征，返回读数 |
| `00002902-0000-1000-8000-00805f9b34fb` | CCCD，`01 00` 开启 Notify |

## 查询和响应映射

官方首页服务就绪时立即查询，另有约 2 秒的轮询周期，查询之间延迟 50 ms。日志称 13 条，实际静态列表列出 12 条。新应用仅使用下表八条，并等待每次 GATT 写入回调后再继续。请求是 12 字节，偏移 0、1、2 为 `F5 55` 与查询码，其余九字节为零。例如温度请求为 `F5 55 8E 00 00 00 00 00 00 00 00 00`。

官方 `onCharacteristicChanged` 只处理 FF22，消息至少 12 字节，类型来自偏移 2，主数据来自偏移 3。涉及温度的指令分支比较 127，超过后加 `-256`，与有符号 int8 等价。值域为整数，单位为 °C。官方分支直接读取该通知，不检查入站头两个字节或尾部校验。图片回调单独检查偏移 1–2 为 `55 16`，无法外推至一般遥测。新应用依照 FF22、长度、类型和值域判定。

| 字段 | 请求 | 响应类型 + 偏移 | 类型与转换 | 状态 |
|---|---|---|---|---|
| 设备温度 | `8E` | `0E` / 3 | int8，乘数 1，°C | APK + DEX 静态确认。传感器位置未识别 |
| 上报功率 | `8D` | `0D` / 3 | uint8，乘数 1，W | 官方界面直接显示 W。测量原理未识别 |
| 风扇档位 | `83` | `03` / 3 | uint8 枚举 0–6 | 官方显示关闭、50%、60%、70%、80%、90%、100%。应用显示枚举档位，RPM 未识别 |
| 功率档位 | `85` | `05` / 3 | uint8 原始档位 | 静态确认存储字段，硬件档位范围待验证 |
| 设备开关 | `82` | `02` / 3 | 枚举 01 开、02 关 | APK 读取与设置映射确认。新应用仅查询 |
| 温控 | `8A` | `0A` / 3 | uint8，0 关闭，非零开启 | 偏移 4 另传至 `wenkong`，其语义待验证 |
| 超频 | `8B` | `0B` / 3 | uint8，0 关闭，非零开启 | 官方界面分支静态确认 |
| 静音 | `8C` | `0C` / 3 | uint8，0 关闭，非零开启 | 官方界面分支静态确认 |

所有表中字段尚待 HCI 抓包与实机行为交叉验证。单字节不涉及端序。响应帧头、尾部语义、CRC、帧序号和设备时间戳未知。应用使用系统接收时刻与单调时钟计算时间及数据新鲜度。图表和历史保存已解析的接收值。

## 其他字段

首页同时查询屏幕亮度、显示模式、图片和速度。它们属于官方 UI 的显示配置路径，当前无充分证据表明速度字段是风扇或水泵转速。水温、进出水温度、制冷端传感器、电压、电流、水泵、故障码及固件版本仍未确认。运行与供电状态来自开关状态枚举，物理制冷状态待实机比对。
