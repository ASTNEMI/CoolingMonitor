# 架构

| 区域 | 实现 | 职责 |
|---|---|---|
| 平台接入 | `BleTransport.kt` | 确切广播名、扫描 12 秒、按地址去重、GATT 回调序列、MTU、服务、单次订阅 |
| 协议 | `Protocol.kt` | 八条只读查询、字节字段、值域和单位 |
| 监控状态 | `Model.kt` | StateFlow 快照、单调时钟、短时重复抑制、过期、断线段、120 条事件 |
| 持久化 | `HistoryStore.kt`、`SettingsStore.kt` | SQLite WAL 记录会话及读数，DataStore 保存显示策略，应用私有存储保存最近设备和布局 |
| 后台 | `MonitorService.kt` | connectedDevice 前台服务、持续接收及轮询、系统通知、蓝牙关闭和停止 |
| 主界面 | `MainActivity.kt`、`Dashboard.kt`、`MonitorPages.kt`、`StyleSurfaces.kt` | Compose 导航、仪表盘、历史、设备、外观和诊断 |
| 悬浮窗 | `OverlayWindow.kt`、`OverlayEditor.kt`、`OverlayDrawing.kt`、`OverlayLayout.kt` | WindowManager、画布坐标、储存、编辑、按模式触摸 |
| 玻璃 | `:backdrop` | 上传附件的 Android 及 common 实现，限定同一 Compose 窗口采样 |

GATT 操作与状态变更串行回到主线程。回调携带的 GATT 必须是当前实例。连接、发现、订阅及写入分别有超时。收到可解析通知后进入「监控中」，无法解析通知时保持计数和有限诊断。连接中断立即将旧数据留在上一段，恢复后同一字段收到新响应才恢复实时。可连续最多重连五次，间隔 2、4、8、15、30 秒。持续收到有效帧达 12 秒后重置当前失败计数。

设备轮询按官方约 2 秒节奏。写入需等待回调，链路慢时实际间隔相应延长。Compose 与悬浮窗按配置抽样最新状态。温度超过 7 秒或跨连接段标为旧值，曲线不跨断线段或采样空档画线。温度趋势保留最多 30 分钟、1000 点，完全由已接收读数组成。

SQLite 在后台串行写入。首次与变动值立即入队。重复温度每 10 秒记录一次，重复状态每 30 秒记录一次，后台服务每小时按保留期限清理。历史列表限最近 160 行，统计、导出和删除覆盖筛选范围。CSV 使用 UTC、会话编号与广播名，设备地址留在应用私有存储。诊断导出包含服务 UUID、阶段、计数、时间和可识别报文的前四字节，省略其他负载。

全局外观保存在 DataStore 中。早期版本的布尔玻璃开关映射到新的界面风格选项，新增强调色支持 RGB。三个渲染范围各有自己的同窗口材质来源。主界面共享应用背景图层，应用弹窗录制本弹窗背景，独立系统悬浮窗使用自己的色层和 Backdrop。在 ColorOS 模式下，应用省略玻璃捕捉，悬浮窗释放玻璃 ComposeView。用户显式选择透明文本，或关闭该布局的跟随样式时，保留该布局外观。
