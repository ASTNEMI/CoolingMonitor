# CX2 Pro 实机验收

需要一台通电的 `NiShen-CX2-pro` 散热器和一台 Android 真机。推荐 OPPO Pad 5 Pro / ColorOS 17。普通安装和蓝牙监控不依赖 Root、Shizuku 或 Termux。本文命令使用 Android SDK Platform Tools。

## 安装、连接和对照

```bash
adb devices -l
adb install -r CoolingMonitor-debug.apk
adb shell am start -n dev.cooling.monitor/.MainActivity
```

首次在应用中授予附近设备权限。Android 9–11 同时开启系统定位。进入「设备 → 搜索附近散热器」，选中刚扫描到的 `NiShen-CX2-pro`。打开「设置 → 通信诊断 → 详细帧记录」。预期依次出现连接、MTU、服务发现、订阅、等待上报和监控中。诊断中应能看到 FF20、FF21、FF22，订阅已开启，接收计数持续增加，解析温度的类型字节为 `0E`。回到仪表盘比对设备端或官方应用的同一时段读数。独立探头可辅助确认传感器位置。

分别比较下面的实机条件并记录温度、通知内容与变化时间。每个档位重复至少三次。

| 条件 | 记录内容 |
|---|---|
| 通电但设备关闭 | `02` 响应值与官方状态 |
| 开机稳定 | `0E` 与官方 °C。观察升温或降温趋势 |
| 调整风扇档位 | `03` 变动、官方显示以及新的档位 |
| 调整功率或模式 | `05`、`0D`、`0A`、`0B`、`0C` 对照 |
| 官方 App 保持连接时运行回路 | 记录能否同时连接及切换所需等待时间 |
| 关散热器复开及关手机蓝牙 | 观察旧值标记、退避、会话连续性与权限异常 |

如果两款应用不能同时使用，按相同设备设置分时录制。电气功率与外部功率表对比前注明测量位置及误差范围。诊断记录导出省略 MAC 和大部分负载。如果发现未知帧，需要在真机上保留原始捕获。

## HCI 捕获

1. 在开发者选项开启「启用蓝牙 HCI 信息收集日志」，按系统提示重启蓝牙。
2. 记录官方 App 和回路的独立会话，注明时间范围、设备型号和固件。
3. 在测试电脑执行 `adb bugreport cooling-ble.zip`。用 `unzip -l cooling-ble.zip | rg -i 'btsnoop|bluetooth'` 查找蓝牙日志路径。包中并非所有系统版本都会提供 HCI 文件。
4. 用 Wireshark 对照 GATT 服务发现、CCCD 的 `01 00`、写入和 FF22 通知。筛选 `btatt`，将相应的属性句柄与服务发现结果配对。发送给协作者前只提取目标散热器会话并遮盖其他设备标识和账户相关数据。

如出现订阅失败，导出诊断以保留状态码、特征属性与 MTU。若通知源正确且解析仍为零，先查长度与类型字节。必要时用 `adb logcat -v threadtime -s BluetoothGatt CoolingHistory AndroidRuntime` 检查系统层错误。

## 后台与长时测试

- 启用悬浮窗，在桌面、普通 App 和目标游戏分别测试拖动、双指缩放、吸边、折叠、锁定、穿透及恢复。旋转两次并核对每个方向的独立位置。
- 测试切后台、锁屏、解锁、分屏、否决通知权限及撤回悬浮窗权限。各录制一次可比较的诊断与历史记录。
- 连续监控至少 2 小时，每 15 分钟收集 `adb shell dumpsys meminfo dev.cooling.monitor`、`adb shell dumpsys gfxinfo dev.cooling.monitor` 与该会话的诊断数据。对照一次后台稳态及一次主动断线。记录 CPU、内存、每组查询延迟、未知通知、重连、帧时间分布和电量变化。
- 验证停止后系统通知消失、悬浮窗被移除，重新启动后历史仍可筛选、导出与删除。
